================================================================================
                        HOW THE IMPROVEMENTS WORK
================================================================================

BACKEND - Save Resume Flow:
  1. User submits form
  2. Validation middleware checks input (XSS prevention)
  3. Controller receives request
  4. Service validates data with Zod schema
  5. Database operation happens
  6. Success response returned with proper format
  7. If any error: Global handler catches it
     → Creates error object with code
     → Logs with context
     → Returns user-friendly message

FRONTEND - Save Resume Flow:
  1. User types in editor
  2. Local state updates (marked dirty)
  3. After 2 seconds of inactivity → auto-save triggered
  4. API client sends POST request
  5. If network fails:
     → Detects failure type
     → Retries with exponential backoff
     → Shows user-friendly message if all retries fail
  6. If success:
     → Updates context
     → Shows success notification
     → Clears dirty flag
  7. Logs entire operation with timing

BACKEND ERROR TYPES:

  Authentication (401):
    - UNAUTHORIZED: No valid token
    - INVALID_USER_ID: Bad user ID format

  Input Validation (400):
    - INVALID_DATA: Bad request format
    - MISSING_RESUME: Resume required
    - EMPTY_RESUME: Resume has no content
    - VALIDATION_ERROR: Field validation failed

  Resource Errors (404):
    - NOT_FOUND: Generic 404
    - NO_RESUME: User has no resume yet

  Conflict (409):
    - CONFLICT: Data conflict

  Server Errors (500):
    - AI_FAILED: AI service error
    - PDF_GENERATION_FAILED: PDF generation error
    - ANALYSIS_FAILED: Analysis failed

  Rate Limiting (429):
    - RATE_LIMITED: Too many requests
